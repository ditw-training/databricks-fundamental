01

Krok 01 — Funkcje PySpark i ich odpowiedniki w SQL

Połącz w paryNierozpoczęty

Komórka konfiguracyjna uruchamia from pyspark.sql import functions as F. F zawiera funkcje znane z SQL: F.year to year(), F.count to COUNT, a F.when to CASE WHEN. Dzięki prefiksowi F wbudowane funkcje Pythona, takie jak sum() czy max(), nadal działają. Dopasuj każde wyrażenie PySpark do kodu SQL, który robi to samo. Przydadzą ci się wszystkie w tym warsztacie.

Przeciągnij każde pojęcie na jego opis albo wybierz je z listy obok opisu.

Pojęcia

  • F.count("*").alias("order_count")
  • F.col("city")
  • F.when(cond, "New").otherwise("Loyal")
  • df.filter(F.col("state") == "NY")
  • F.col("order_datetime").cast("timestamp")
  • F.year(F.col("registration_date"))

Oczekiwany wynik

Wszystkie sześć par dopasowanych.

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Czytaj kod PySpark jak SQL: nazwa funkcji zwykle się nie zmienia (year → year, count → COUNT).

  2. Podpowiedź 2

    .alias(...) to w SQL AS, .otherwise(...) to ELSE, a .filter(...) staje się klauzulą WHERE.

  3. Rozwiązanie

    Pary: F.col("city") → city; F.year(...) → year(registration_date); F.count("*").alias(...) → COUNT(*) AS order_count; F.when(...).otherwise(...) → CASE WHEN ... END; .cast("timestamp") → CAST(... AS TIMESTAMP); df.filter(...) → WHERE state = 'NY'.

    Krok 03 — Wczytaj CSV z jawnym schematem

    Uzupełnij lukiNierozpoczęty

Spark pomija wtedy dodatkowe skanowanie, a ty decydujesz o każdym typie. Kolumny CSV są dopasowywane po pozycji, więc kolejność musi być taka jak w pliku. registration_date ma format YYYY-MM-DD, więc DATE odczyta ją bezpośrednio.

    Odpowiednik w SQL: read_files('<path>/customers.csv', format => 'csv', header => true, schema => 'customer_id STRING, ...').

    Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny.

    # Schema as a DDL string: 10 columns in the CSV order
customers_schema = (
    "customer_id STRING, first_name STRING, last_name STRING, email STRING, phone STRING, "
    "city STRING, state STRING, country STRING, registration_date , customer_segment STRING"
)

# Load the CSV with the explicit schema (no inferSchema)
customers_df = (
    spark.read
    .format("csv")
    .option("", "true")
    .(customers_schema)
    .load()
)
display(customers_df.limit(5))

# saves your result so the app can check it

    Napisz kodOpcjonalnyNierozpoczęty

 .write.mode("overwrite").option("overwriteSchema", "true").saveAsTable(f"{CATALOG}.default._ws_ws_ingestion_t06"))

    07

    Krok 07 — Dodaj kolumny i zmień typy

    Uzupełnij lukiNierozpoczęty

    df.withColumn("name", expression) zwraca nowy DataFrame z jedną kolumną więcej; kilka wywołań łączysz w łańcuch w nawiasach. F.concat_ws(" ", a, b) łączy napisy separatorem i pomija NULL. .cast("timestamp") zamienia tekst taki jak 2024-12-31T23:56:00 na znacznik czasu; NULL zostaje NULL. Jeśli tekstu nie da się przekonwertować, Databricks zgłasza błąd; try_cast zwraca wtedy NULL. W drugiej luce wpisz separator razem z cudzysłowami: " ".

    Odpowiedniki w SQL: SELECT *, concat_ws(' ', first_name, last_name) AS full_name, year(registration_date) AS registration_year FROM customers_view oraz SELECT *, CAST(order_datetime AS TIMESTAMP) AS order_ts FROM orders_view.

    Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny.

    # customers_enriched: full_name and registration_year
customers_enriched = (
    customers_df
    .("full_name", F.concat_ws(, F.col("first_name"), F.col("last_name")))
    .withColumn("registration_year", F.(F.col("registration_date")))
)

# orders_typed: order_datetime (STRING) cast to TIMESTAMP
orders_typed = orders_df.withColumn("order_ts", F.col("order_datetime").("timestamp"))

display(customers_enriched.select("customer_id", "full_name", "registration_year").limit(5))
display(orders_typed.select("order_id", "order_datetime", "order_ts").limit(5))

# saves your result so the app can check it
(customers_enriched.withColumn("_part", F.lit("customers")).unionByName(orders_typed.withColumn("_part", F.lit("orders")), allowMissingColumns=True)
 .write.mode("overwrite").option("overwriteSchema", "true").saveAsTable(f"{CATALOG}.default._ws_ws_ingestion_t07"))

    Oczekiwany wynik

    customers_enriched ma full_name (STRING) i registration_year (INT); orders_typed ma order_ts (TIMESTAMP) i nie ma nowych wartości NULL.

    Podpowiedzi dostępne: 3

    1. Podpowiedź 1

      Linia tuż pod luką już używa metody, która dodaje kolumnę. Separator między imieniem a nazwiskiem to jedna spacja w cudzysłowie.

    2. Podpowiedź 2

      Nazwy funkcji PySpark są takie jak w SQL: year(...) i CAST(...) to F.year(...) i .cast(...).

    3. Rozwiązanie

      Luki: withColumn, " ", year, cast.

    08

    Krok 08 — Kolumna warunkowa: segment klienta

    Uzupełnij lukiNierozpoczęty

    F.when(condition, value) zaczyna wyrażenie warunkowe, .when(...) dodaje kolejne gałęzie, a .otherwise(value) to ELSE. Wygrywa pierwsza pasująca gałąź, więc sprawdź >= 2025 przed >= 2024. Bez .otherwise() niepasujące wiersze dostają NULL. Reguły: registration_year >= 2025 → New, >= 2024 → Regular, w pozostałych przypadkach Loyal.

    Odpowiednik w SQL: CASE WHEN year(registration_date) >= 2025 THEN 'New' WHEN ... ELSE 'Loyal' END AS customer_tier.

    Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny.

    # customer_tier: >= 2025 -> New, >= 2024 -> Regular, otherwise -> Loyal
customers_tiered = customers_enriched.withColumn(
    "customer_tier",
    F.when(F.col("registration_year") >= , "New")
    .(F.col("registration_year") >= 2024, "Regular")
    .("Loyal")
)

display(customers_tiered.groupBy("customer_tier").count().orderBy("customer_tier"))

# saves your result so the app can check it
