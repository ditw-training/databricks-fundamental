A Delta table is created from the rows of a query or a DataFrame in one step. On Databricks every new table is a Delta table by default, so you do not need to name the format. Without a storage location the table is managed: Unity Catalog stores the files for you. Replacing an existing table lets you run the code again without an error.

CREATE TABLE ... AS SELECT (CTAS) creates the table and loads the rows of a query in one statement, and OR REPLACE makes it safe to run again. You do not need USING DELTA. The source is the temporary view customers_csv from the ready cell of the notebook.

A CHECK constraint is a rule that Delta tests on every write. Adding it first verifies the existing rows, then every later write that breaks the rule is rejected. You add valid_country with the condition country IS NOT NULL, then try to insert customer BAD_C with a NULL country: that insert must fail.

iThis step is optional: you can skip it; the next steps do not depend on it.

ALTER TABLE ... ADD CONSTRAINT <name> CHECK (<condition>) adds the rule. The first line drops the constraint if it exists, so you can run the code again. The last statement must end with an error. Check on data for this step needs the PySpark cell, which saves the error message.

Step 08 — MERGE INTO (upsert)

OrderNot started

MERGE INTO combines update and insert in one atomic statement (an upsert). ON says how a source row finds its target row: here by customer_id. WHEN MATCHED updates customers that already exist, WHEN NOT MATCHED inserts new ones. The source is the temporary view updates_view from the ready cell. Two blocks are traps.

iIn PySpark the same upsert is DeltaTable.forName(spark, TABLE).merge(...) with a column map for every column, so both tracks use the shorter SQL statement. In a Python cell you run it with spark.sql(...).
