01

Krok 01 — Utwórz tabelę Delta

Uzupełnij lukiNierozpoczęty

CREATE TABLE ... AS SELECT (CTAS) tworzy tabelę i ładuje do niej wiersze zapytania w jednej instrukcji. Na Databricks każda nowa tabela jest domyślnie tabelą Delta, więc nie potrzebujesz USING DELTA. Bez LOCATION tabela jest zarządzana (managed): pliki przechowuje za ciebie Unity Catalog. OR REPLACE pozwala uruchomić komórkę ponownie bez błędu.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny.

CREATE OR REPLACE  lab_delta_cust_ws 
SELECT * FROM

Oczekiwany wynik

Tabela lab_delta_cust_ws istnieje, ma format delta i tyle samo wierszy co customers_csv (10 000).

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Tworzysz tabelę z wyniku zapytania: instrukcja to CREATE OR REPLACE TABLE <name> AS <query>.

  2. Podpowiedź 2

    Zapytanie czyta wszystkie kolumny widoku tymczasowego: SELECT * FROM customers_csv.

  3. Rozwiązanie

    Pełne rozwiązanie:

    CREATE OR REPLACE TABLE lab_delta_cust_ws AS
SELECT * FROM customers_csv

Krok 02 — Wymuszanie schematu

Napisz kod⭐ OpcjonalnyNierozpoczęty

Delta sprawdza każdy zapis względem schematu tabeli (schema enforcement). DataFrame z kolumną, której tabela nie ma, zostaje odrzucony i nic nie jest zapisywane: zapis kończy się błędem w całości. Tutaj dopisujesz bad_df w gotowym bloku try. try / except to sposób Pythona na przechwycenie błędu: jeśli linia pod try: się nie powiedzie, Python przechodzi do except, a błąd trafia do enforcement_error i nie zatrzymuje notebooka. Zamieniasz tylko pass na jedną linię. Odpowiednik w SQL: INSERT INTO lab_delta_cust_ws (customer_id, mood) VALUES ('BAD001', 'happy') kończy się takim samym błędem.

Napisz kod w komórce notebooka. Komórka zaczyna się tak:

try:
    # YOUR CODE HERE: append bad_df to TABLE

    enforcement_error = str(e)

Krok 03 — Ewolucja schematu: dodaj kolumnę

Uzupełnij lukiNierozpoczęty

Czasem schemat trzeba zmienić celowo: to schema evolution (ewolucja schematu). ALTER TABLE ... ADD COLUMN dodaje kolumnę, zmieniając tylko metadane tabeli w dzienniku transakcji; pliki danych nie są przepisywane. Istniejące wiersze mają w nowej kolumnie NULL, dopóki ich nie zaktualizujesz. W pierwszej luce wpisz dwuwyrazową klauzulę ADD COLUMN, a w drugiej nazwę kolumny.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny.

ALTER TABLE lab_delta_cust_ws   STRING

Oczekiwany wynik

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Instrukcja, która zmienia strukturę tabeli, to ALTER TABLE; potrzebujesz klauzuli, która dodaje kolumnę.

  2. Podpowiedź 2

    Wzorzec: ALTER TABLE <table> ADD COLUMN <name> <type>.

  3. Rozwiązanie

    Pełne rozwiązanie:

    ALTER TABLE lab_delta_cust_ws ADD COLUMN loyalty_tier STRING

04

Krok 04 — Ograniczenie CHECK

Napisz kod⭐ OpcjonalnyNierozpoczęty

Ograniczenie CHECK to reguła, którą Delta sprawdza przy każdym zapisie. ALTER TABLE ... ADD CONSTRAINT najpierw weryfikuje istniejące wiersze, a potem odrzuca każdy zapis, który łamie regułę. Dodajesz valid_country z warunkiem country IS NOT NULL, a potem w gotowym bloku try wstawiasz klienta BAD_C z krajem NULL (jeśli INSERT się nie powiedzie, except zapisze błąd w constraint_error, a notebook będzie działał dalej). SQL uruchamiasz z Pythona przez spark.sql(f"..."), a nazwę tabeli wstawiasz jako {TABLE}. Pierwsza linia jest gotowa: usuwa ograniczenie, jeśli istnieje, więc możesz uruchomić komórkę ponownie.

Napisz kod w komórce notebooka. Komórka zaczyna się tak:

# Step 04: add the constraint, then try to break it
constraint_error = None
spark.sql(f"ALTER TABLE {TABLE} DROP CONSTRAINT IF EXISTS valid_country")  # lets you re-run this cell
# 1. Add the CHECK constraint valid_country: country IS NOT NULL
# YOUR CODE HERE

# 2. Insert customer_id 'BAD_C' with country NULL (it must fail)
try:
    # YOUR CODE HERE
    pass
except Exception as e:
    constraint_error = str(e)
print(f"Insert rejected: {constraint_error is not None}")

# saves your result so the app can check it
(spark.createDataFrame([(constraint_error,)], "error STRING")
 .write.mode("overwrite").option("overwriteSchema", "true").saveAsTable(f"{CATALOG}.default._ws_ws_delta_t04"))

Nie wiesz, jak zacząć? Otwieraj podpowiedzi poniżej po jednej; ostatnia to pełne rozwiązanie.

Oczekiwany wynik

SHOW TBLPROPERTIES pokazuje delta.constraints.valid_country, constraint_error zawiera błąd, a BAD_C nie ma w tabeli.

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Dwie instrukcje: ALTER TABLE ... ADD CONSTRAINT <name> CHECK (<condition>), potem INSERT z NULL w country.

  2. Podpowiedź 2

    SQL to ALTER TABLE ... ADD CONSTRAINT valid_country CHECK (country IS NOT NULL), a potem INSERT INTO ... (customer_id, country) VALUES ('BAD_C', NULL). W Pythonie spark.sql(f"...") uruchamia jedną instrukcję SQL, a {TABLE} wstawia nazwę tabeli.

  3. Rozwiązanie

    Pełne rozwiązanie:

    constraint_error = None
spark.sql(f"ALTER TABLE {TABLE} DROP CONSTRAINT IF EXISTS valid_country")  # lets you re-run this cell
spark.sql(f"ALTER TABLE {TABLE} ADD CONSTRAINT valid_country CHECK (country IS NOT NULL)")
try:
    spark.sql(f"INSERT INTO {TABLE} (customer_id, country) VALUES ('BAD_C', NULL)")
except Exception as e:
    constraint_error = str(e)
print(f"Insert rejected: {constraint_error is not None}")

# saves your result so the app can check it
(spark.createDataFrame([(constraint_error,)], "error STRING")
 .write.mode("overwrite").option("overwriteSchema", "true").saveAsTable(f"{CATALOG}.default._ws_ws_delta_t04"))
Pokazać pełne rozwiązanie? Więcej się nauczysz, jeśli spróbujesz jeszcze raz z podpowiedziami, które już masz.

Krok 05 — Wstaw klientów testowych (INSERT)

Uzupełnij lukiNierozpoczęty

INSERT INTO ... VALUES dodaje wiersze do tabeli. Kolumny wymień po nazwie tabeli; pominięte kolumny (tu loyalty_tier, phone, ...) dostają NULL. Jedna instrukcja z kilkoma wierszami w VALUES to jeden atomowy zapis i jedna nowa wersja tabeli. Uruchom komórkę tylko raz: drugie uruchomienie wstawi te wiersze ponownie.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny.

INSERT INTO lab_delta_cust_ws (customer_id, first_name, last_name, email, country)
 ('TEST001', 'Alice', 'Test', 'alice@test.com', ),

       ('TEST003', 'Carol', 'Test', 'carol@test.com', 'TestLand')

Oczekiwany wynik

Tabela zawiera TEST001, TEST002 i TEST003, każdy dokładnie raz, wszystkie z krajem TestLand.

  2. Podpowiedź 2

Krok 06 — Zaktualizuj jednego klienta (UPDATE)

Uzupełnij lukiNierozpoczęty

UPDATE ... SET ... WHERE zmienia kolumny w wierszach, które spełniają warunek. SET może zmienić kilka kolumn naraz, oddzielonych przecinkami. Zawsze dodawaj WHERE: bez niego zmienisz każdy wiersz tabeli. Stare wartości można odczytać przez time travel, dopóki VACUUM nie usunie starych plików.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny.

UPDATE lab_delta_cust_ws
SET country = 'Poland',  = 'Gold'
 customer_id = 'TEST001'

Oczekiwany wynik

TEST001 ma kraj Poland i poziom lojalności Gold; żaden inny wiersz nie ma poziomu Gold.

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Druga kolumna do zmiany to kolumna dodana w kroku 03.

  2. Podpowiedź 2

    Ostatnia linia ogranicza zmianę do jednego klienta: zaczyna się od słowa kluczowego, które filtruje wiersze.

  3. Rozwiązanie

    Pełne rozwiązanie:

    UPDATE lab_delta_cust_ws
SET country = 'Poland', loyalty_tier = 'Gold'
WHERE customer_id = 'TEST001'

08

Krok 08 — MERGE INTO (upsert)

Ułóż w kolejnościNierozpoczęty

MERGE INTO łączy aktualizację i wstawianie w jednej atomowej instrukcji (upsert). ON mówi, jak wiersz źródłowy znajduje swój wiersz docelowy: tu po customer_id. WHEN MATCHED aktualizuje klientów, którzy już istnieją, a WHEN NOT MATCHED wstawia nowych. Ułóż bloki w aplikacji, potem wklej instrukcję do notebooka. Dwa bloki to pułapki.

Przeciągnij bloki do sekcji Twoja odpowiedź we właściwej kolejności albo użyj przycisków Dodaj, ↑, ↓ i ✕. 2 bloki to pułapki i muszą zostać poza odpowiedzią.

Dostępne bloki

  • ⋮⋮
    ON t.customer_id = s.customer_id
  • ⋮⋮
    WHEN MATCHED THEN UPDATE SET
  first_name = s.first_name, last_name = s.last_name, email = s.email,
  country = s.country, loyalty_tier = s.loyalty_tier
  • ⋮⋮
    ON t.email = s.email
  • ⋮⋮
    WHEN NOT MATCHED BY SOURCE THEN DELETE
  • ⋮⋮
    USING updates_view AS s
  • ⋮⋮
    MERGE INTO lab_delta_cust_ws AS t
  • ⋮⋮
    WHEN NOT MATCHED THEN INSERT (customer_id, first_name, last_name, email, country, loyalty_tier)
  VALUES (s.customer_id, s.first_name, s.last_name, s.email, s.country, s.loyalty_tier)

Twoja odpowiedź

    Upuść bloki tutaj.

    Oczekiwany wynik

    Zaktualizowano 2 klientów (TEST001 staje się MergedAlice, poziom Platinum), wstawiono 1 (MERGE_NEW), pozostali klienci bez zmian.

    Podpowiedzi dostępne: 3

    1. Podpowiedź 1

      Instrukcję czyta się jak zdanie: tabela docelowa, źródło, warunek złączenia, a potem co zrobić z wierszami dopasowanymi i niedopasowanymi.

    2. Podpowiedź 2

      Klientów identyfikuje customer_id, a nie email (w tej partii adresy e-mail się zmieniają). WHEN NOT MATCHED BY SOURCE THEN DELETE usunąłby każdego klienta, którego nie ma w partii.

    3. Rozwiązanie

      Pełne rozwiązanie:

      MERGE INTO lab_delta_cust_ws AS t
USING updates_view AS s
ON t.customer_id = s.customer_id
WHEN MATCHED THEN UPDATE SET
  first_name = s.first_name, last_name = s.last_name, email = s.email,
  country = s.country, loyalty_tier = s.loyalty_tier
WHEN NOT MATCHED THEN INSERT (customer_id, first_name, last_name, email, country, loyalty_tier)
  VALUES (s.customer_id, s.first_name, s.last_name, s.email, s.country, s.loyalty_tier)

      Napisz kod⭐ OpcjonalnyNierozpoczęty

      Time travel działa też z punktem w czasie: TIMESTAMP AS OF '<timestamp>'. INSERT z kroku 05 to najnowszy wiersz historii z operation = 'WRITE' i operationParameters.mode = 'Append'.
