Krok 01 — Utwórz tabelę Delta

Uzupełnij lukiUzupełnij lukiNierozpoczęty

Tabelę Delta tworzysz z wierszy zapytania albo DataFrame w jednym kroku. Na Databricks każda nowa tabela jest domyślnie tabelą Delta, więc nie musisz podawać formatu. Bez lokalizacji danych tabela jest zarządzana (managed): pliki przechowuje za ciebie Unity Catalog. Zastąpienie istniejącej tabeli pozwala uruchomić kod ponownie bez błędu.

CREATE TABLE ... AS SELECT (CTAS) tworzy tabelę i ładuje do niej wiersze zapytania w jednej instrukcji, a OR REPLACE pozwala uruchomić ją ponownie. Nie potrzebujesz USING DELTA. Źródłem jest widok tymczasowy customers_csv z gotowej komórki notebooka.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny; krok jest zaliczony, gdy poprawne są wszystkie.

CREATE OR REPLACE  lab_delta_cust_ws 
SELECT * FROM

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Tworzysz tabelę z wyniku zapytania: instrukcja to CREATE OR REPLACE TABLE <name> AS <query>.

  2. Podpowiedź 2

    Zapytanie czyta wszystkie kolumny widoku tymczasowego: SELECT * FROM customers_csv.

  3. Rozwiązanie

    Pełne rozwiązanie:

    CREATE OR REPLACE TABLE lab_delta_cust_ws AS

Krok 02 — Wymuszanie schematu

Uzupełnij lukiUzupełnij lukiOpcjonalnyNierozpoczęty

Delta sprawdza każdy zapis względem schematu tabeli (schema enforcement). Zapis z kolumną, której tabela nie ma, zostaje odrzucony i nic nie jest zapisywane: zapis kończy się błędem w całości. Tutaj próbujesz dodać klienta BAD001 z dodatkową kolumną mood.

iTen krok jest opcjonalny: możesz go pominąć, kolejne kroki go nie wymagają.

Uruchom instrukcję i przeczytaj błąd: Delta podaje kolumnę, której nie może znaleźć. Instrukcja zakończona błędem niczego nie zmienia, więc tabela nie dostaje nowej wersji. Sprawdź na danych w tym kroku wymaga komórki PySpark, która zapisuje komunikat błędu.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny; krok jest zaliczony, gdy poprawne są wszystkie.

-- This statement must fail: the table has no column mood
INSERT INTO lab_delta_cust_ws (customer_id, )
 ('BAD001', 'happy');

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Wpisz dodatkową kolumnę po customer_id, jak każdą inną kolumnę w INSERT.

  2. Podpowiedź 2

    Słowo kluczowe przed listą wierszy jest takie samo jak w każdym INSERT INTO ... (columns).

  3. Rozwiązanie

    Pełne rozwiązanie:

    -- This statement must fail: the table has no column mood
INSERT INTO lab_delta_cust_ws (customer_id, mood)
VALUES ('BAD001', 'happy');

Krok 03 — Ewolucja schematu: dodaj kolumnę

Uzupełnij lukiNierozpoczęty

Czasem schemat trzeba zmienić celowo: to schema evolution (ewolucja schematu). Dodanie kolumny zmienia tylko metadane tabeli w dzienniku transakcji; pliki danych nie są przepisywane. Istniejące wiersze mają w nowej kolumnie NULL, dopóki ich nie zaktualizujesz.

iZmiana schematu to instrukcja SQL w obu ścieżkach. W komórce Pythona uruchamiasz ją przez spark.sql(f"ALTER TABLE {TABLE} ADD COLUMN loyalty_tier STRING").

ALTER TABLE ... ADD COLUMN dodaje kolumnę. W pierwszej luce wpisz dwuwyrazową klauzulę ADD COLUMN, a w drugiej nazwę kolumny.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny; krok jest zaliczony, gdy poprawne są wszystkie.

ALTER TABLE lab_delta_cust_ws   STRING

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

  2. Podpowiedź 2

  3. Rozwiązanie

04

Krok 04 — Ograniczenie CHECK

Uzupełnij lukiUzupełnij lukiOpcjonalnyNierozpoczęty

Ograniczenie CHECK to reguła, którą Delta sprawdza przy każdym zapisie. Jego dodanie najpierw weryfikuje istniejące wiersze, a potem każdy zapis, który łamie regułę, jest odrzucany. Dodajesz valid_country z warunkiem country IS NOT NULL, a potem próbujesz wstawić klienta BAD_C z krajem NULL: to wstawienie musi się nie udać.

iTen krok jest opcjonalny: możesz go pominąć, kolejne kroki go nie wymagają.

ALTER TABLE ... ADD CONSTRAINT <name> CHECK (<condition>) dodaje regułę. Pierwsza linia usuwa ograniczenie, jeśli istnieje, więc możesz uruchomić kod ponownie. Ostatnia instrukcja musi zakończyć się błędem. Sprawdź na danych w tym kroku wymaga komórki PySpark, która zapisuje komunikat błędu.

Wpisz brakujące fragmenty. Luka zmienia kolor na zielony, gdy wpis jest poprawny; krok jest zaliczony, gdy poprawne są wszystkie.

ALTER TABLE lab_delta_cust_ws DROP CONSTRAINT IF EXISTS valid_country;  -- lets you re-run
ALTER TABLE lab_delta_cust_ws ADD  valid_country  (country IS NOT NULL);

-- This INSERT must fail: country is NULL
INSERT INTO lab_delta_cust_ws (customer_id, country) VALUES ('BAD_C', );

Podpowiedzi dostępne: 3

  1. Podpowiedź 1

    Dwa słowa kluczowe nazywają regułę i jej typ: reguła to ograniczenie (constraint), a jej typ to sprawdzenie (check).

  2. Podpowiedź 2

    Wzorzec: ALTER TABLE ... ADD CONSTRAINT valid_country CHECK (country IS NOT NULL); brakująca wartość w VALUES to NULL.

  3. Rozwiązanie

    Pełne rozwiązanie:

    ALTER TABLE lab_delta_cust_ws DROP CONSTRAINT IF EXISTS valid_country;  -- lets you re-run
ALTER TABLE lab_delta_cust_ws ADD CONSTRAINT valid_country CHECK (country IS NOT NULL);

-- This INSERT must fail: country is NULL
INSERT INTO lab_delta_cust_ws (customer_id, country) VALUES ('BAD_C', NULL);

Jedna instrukcja z kilkoma wierszami w VALUES to jeden atomowy zapis i jedna nowa wersja tabeli. Jeśli uruchamiasz kod, zrób to raz: drugie uruchomienie wstawi wiersze ponownie.

iINSERT INTO ... VALUES to najkrótszy sposób na dodanie kilku wierszy, więc obie ścieżki go używają. W komórce Pythona uruchamiasz go przez spark.sql(...).

       ('TEST003', 'Carol', 'Test', 'carol@test.com', 'TestLand')

Uzupełnij lukiNierozpoczęty

UPDATE ... SET ... WHERE zmienia kolumny w wierszach, które spełniają warunek. SET może zmienić kilka kolumn naraz, oddzielonych przecinkami. Zawsze dodawaj WHERE: bez niego zmienisz każdy wiersz tabeli. Stare wartości można odczytać przez time travel, dopóki VACUUM nie usunie starych plików.

UPDATE lab_delta_cust_ws
SET country = 'Poland',  = 'Gold'
 customer_id = 'TEST001'

Krok 08 — MERGE INTO (upsert)

Ułóż w kolejnościNierozpoczęty

MERGE INTO łączy aktualizację i wstawianie w jednej atomowej instrukcji (upsert). ON mówi, jak wiersz źródła znajduje swój wiersz docelowy: tutaj po customer_id. WHEN MATCHED aktualizuje istniejących klientów, a WHEN NOT MATCHED wstawia nowych. Źródłem jest widok tymczasowy updates_view z gotowej komórki. Dwa bloki to pułapki.

        Krok 12 — RESTORE po przypadkowym usunięciu

        Ułóż w kolejnościUłóż w kolejnościNierozpoczęty

        DELETE FROM <table> bez WHERE usuwa wszystkie wiersze, ale stara wersja nadal jest w historii. RESTORE TABLE ... TO VERSION AS OF <n> przywraca tabelę do wersji n i zapisuje przywrócenie jako nową wersję. Time travel to nie kopia zapasowa: po tym, jak VACUUM usunie stare pliki danych, tych wersji już nie ma. Najpierw wypadek i jego skutek, potem naprawa i jej skutek; dwa bloki to pułapki.

        Uruchom pierwszą linię osobno, przed wypadkiem, i zanotuj wersję, którą pokaże: to twoja bezpieczna wersja. Wpisz ten numer w miejsce <safe version>.
